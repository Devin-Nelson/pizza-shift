# Dominus Pizza (Roblox)

Roblox pizza job game turning tycoon/simulator: a spiritual successor to "Work at a Pizza Place". Every station is a skill minigame on a 3D pizza; each player opens their own store on a lot (or joins one, up to 4 players) and hires NPC staff to run it with them. Store operations are modeled on a delivery-first pizza chain (Domino's-style) **under our own brand**. Never use a real chain's name, logo, or trade dress; it would risk a Roblox IP takedown. Goal: ship ASAP, then monetize (game passes) and polish.

## Workflow
- Rojo 7.7.1 lives at `%USERPROFILE%\.rojo\bin\rojo.exe` (not on PATH). The Studio plugin is installed.
- Live sync: `rojo serve` in this folder, then Connect in the Studio Rojo plugin. Build check: `rojo build -o test.rbxlx`.
- Checks (binaries from the luau-lang/luau GitHub release): `luau-compile --null <file>` for syntax; `luau-analyze <file>` for lint (ignore Roblox globals/types it doesn't know; look for Unused/Shadow warnings and any unknown global that isn't a Roblox built-in). Only Studio playtesting catches runtime errors, so ask the user for Output-window errors or screenshots.
- More checks, from the repo root (tools in `~/.rokit/bin`): `lune run tests/specs` (headless specs: loads the real Config, GameClock, SalesPlan, Style, TicketRows and DataService (fake DataStore for the save lock) with stubbed engine globals; add a spec for every new pure rule) and `selene src` (must stay at 0 errors, 0 warnings). StyLua isn't used: the code's long-line style isn't stylua's.
- Studio MCP notes: every `execute_luau` call resets the camera to Custom (so a station's camera can't be inspected live: rebuild it from `Config.StationView` instead), the viewport can report 1x1 while Studio isn't rendering, and screenshots can time out mid-run (a minigame session then times out at 120 s).
- Studio MCP (server "Roblox_Studio") can run playtests: `start_stop_play`, `execute_luau` on the Server/Client datamodels, `get_console_output`. A scripted run fires the real remotes from the Client datamodel (the server's validation and min-time checks still apply) to drive every station headlessly. The mouse/keyboard input tools use GUI coordinates (no top-bar inset); Studio stopped rendering partway through one clicked run, so save clicked/recorded runs for milestones.
- The map is built entirely in code; MapBuilder deletes Studio's default Baseplate/SpawnLocation on start (the Baseplate z-fights with our grass).
- If Studio shows something the code no longer does (e.g. old station labels), the Rojo plugin has disconnected and Studio is running stale scripts. Reconnect before testing.

## Architecture
- `src/shared/Config.luau`: all balance, stations and the make steps, the menu (sizes, toppings, prices, portions), brand, clock and sales tuning. Change numbers here first.
- `src/shared/Remotes.luau`: RemoteEvents (server creates, client waits).
- `src/shared/GameClock.luau` + `src/server/ClockService.luau`: 24h clock (ReplicatedStorage "WeekHour" attribute, 0-168 from Monday 00:00), sun, `Closed` event at midnight. `GameClock.hoursText()` builds hours text from Config.
- `src/shared/Pizza3D.luau`: 3D pizza builder used by client minigames and the server's oven/belt visuals (same seed = same layout).
- `src/server/MapBuilder.luau`: map, store layout (`BuildShop`), houses (16), store lots (5, empty until a store opens). `StationArt.luau`: station visuals; a Model in `ServerStorage/StationModels/<Kind>` overrides the generated art.
- `src/server/ShopService.luau`: order flow from the sales forecast (walk-in/phone/online, 1-30 pizzas), dough skins on two 15-slot screen racks (30 slots, any sizes, oldest of a size used first), and a free-form make process: **pies** (physical pizzas, `shop.pies`) are made without an order (Sauce picks any skin size → "Sauced" → Cheese → "Cheesed" → Toppings → "Ready" on the 15-slot ready rack, `readySlot`; a toppings job only starts if `readyRoom` has a slot for it), and `loadPie` puts one in the next free oven slot (round-robin 1-6, waits for the lane entrance to clear) and matches it to an order **ticket** (`matchTicket`: auto, or the order the player picked; none = an extra). Toppings are scored and paid at load time. `ovenStep` (10 Hz) moves pies along their lane in real time (`Config.Oven.BakeTime`), browns them between the chamber mouths (`Pizza3D.bakeTint`), makes them pullable ("Exit") the moment the leading edge clears the exit mouth, backs them up at the end of the belt and drops the front one `FallAfter` seconds after it reaches the end. The oven tender pulls any pie that is out (Cut session; putting it down returns it to its lane), boxes it; when every ticket of an order is boxed the order goes to carryout or the heat rack. Load time = placed → last pie loaded; total time = placed → last pie boxed. Stock, open hours, **server-authoritative** scoring and pay, management slots.
- `src/server/SalesPlan.luau`: weekly forecast, day/daypart split, order-size rolls, pricing. `CarService.luau`: per-driver cars, network-owned by the driver. `DataService.luau`: DataStore saves (profile `Staff` = the player's hires).
- `src/server/StoreService.luau`: the 5 store lots (MapBuilder; lot 1 is the old HQ site, stores are built when opened). Store picker (`OpenStorePicker` / `ChooseStore` / `RequestStores`), membership (`ShopService.SetMember`, player attributes `StoreId` and `StoreOwner`, max `Config.Store.MaxPlayers`), owner handover (longest-serving member, store rebuilt as theirs), and the Staff menu (`RequestStaff` / `HireStaff` / `AssignStaff` / `ScheduleStaff` / Studio-only `GrantStaff` -> `OpenStaffMenu`; owner-only changes; `assign` moves a team member or toggles a manager's station; `prepareStaff` sanitizes the owner's saved staff once as their store opens; changes push with `ShopService.SetCrew`).
- Staff rules live in `src/shared/Staff.luau` (pure, specced): shifts (`shiftAt`: the sales dayparts, Lunch starting with prep at 9:30), station levels and XP (`xpToNext`, `addXP`), what a level does (`quality`, `speed`), call-outs (`calloutChance`), managers' Flexibility (`stationLimit`, `overload`, `jobQuality`, `jobSpeed`), new hires (`newMember` from `Config.StaffGen`), save repair (`sanitize`), the roll (`rollKind`). Hired staff at work live in ShopService ("Hired staff (NPCs)" section): `shop.crew` holds each member's saved record (XP is written straight into the owner's profile), `startShift` rolls call-outs as a shift begins and `crewRoster` brings in whoever's scheduled; `crewStep` ticks once a second (`crewStart` looks for work across a member's stations, `crewJobAt` / `crewFinish` / `releaseCrew`). Every station step's core is one shared function (`saucePie`, `cheesePie`, `topPie`, `pullPie`, `boxPie`, `loadPie` with `player` nil) called by both a player's minigame result and the staff, so the rules can't drift. Staff only sauce/top what open orders still need (`neededSize`, `neededToppings`, `doughNeed`), stretch needed sizes first, and only load exact topping matches; at the heat rack they drive (walk to the driver door, vanish for `Config.StaffWork.Trip` x their speed, complete the order). NPCs are tagged `CrewNPC`; the client hides one standing where its player works (Workstation). Delivery orders need 2+ players or someone on shift with the heat rack among their stations, else they arrive as carryout (`takesDeliveries`).
- Staying at a station: Config.Stations `stay` stations (Register, Dough, Sauce, Cheese, Toppings, Load, CutTable, DeliveryRack) are server-tracked (`stationed` in ShopService). `useStation` is the single entry point (prompts, `UseStation(station, pickId?)`); `enterStation` fires `StationMode` to the client, then `assign` starts the next job there (also every tick and `Config.NextJobDelay` after each step, longest-waiting player first) or sends a `StationStatus` "waiting for..." text. `pick` stations (Load, CutTable, DeliveryRack) never auto-start: `startStation` needs a pickId (the exit pie / the order); at Load it only ever returns a status, loading goes through `LoadPizza`. A delivery doesn't hold the station (`holdsStation`): taking one takes you off it. `startStation` returns nil when a job started, else that reason. `LeaveStation` / X / Exit leaves; a session timeout while stationed also leaves (AFK guard). `LoadPizza(pieId, orderId?)` loads from the ready rack (only while stationed at Load; orderId 0 = extra, nil = auto); the toppings minigame's "Load It" loads straight from its result.
- Kitchen layout (shop-local): dough table x -20.5, make-line x -3.5 (17 wide, 4.7 deep with a 2.9-deep grate so a Large on its screen fits) and the ready rack table x 7.6 in a row at z 4 facing the counter; three stacked ovens at (15.5, -3) running from the make-line end (+Z) back to the exit end (-Z); cut table at (6, -10.4) beside the exits; heat rack at (-3.5, -10.4). The oven exits face the oven tender, so all six are visible from the cut table camera.
- No job aid cards (user, 2026-10-19): each station's first-visit tip card (`StationTips`, reopened with Help) carries its reference chart, built from Config: the sauce line, cheese ounces, topping portions (1 / 2-3 toppings, pieces or oz), slices.
- Make-process flow (ShopService `assign`, `hasWork`, `occupant`): at a make station (`Config.MakeSteps`: Dough, Sauce, Cheese, Toppings, Load) with nothing to work, a player is moved back a step (`Config.StepBefore`) unless someone is there (then "waiting on X at Y"). `stepDone` tells the client the pizza's next step (`Config.StepAfter`, or the cut table once loaded) and whether it's free now (`ready`); the snapshot's `occupied` and `pieAt` keep the Next button current. Stretch and Sauce get `need` (the size the oldest ticket still needs) to highlight.
- Make-line scales and pans (StationArt): a `ScalePlate` and `ScaleDisplay` (`Scale` = station) at the cheese and toppings spots; the client writes the weight on the display locally (`Minigames3D.scaleDisplay`). Topping pans (`Pan_<name>`, `Topping` attribute) sit in front of the toppings spot; the toppings minigame picks one by raycast click.
- `src/client/`: `Main.client.luau` (status pill, store picker and Staff menus, prompt filtering to your own store's stations, delivery waypoint, pay slips), `Ui.luau` (the toolkit: a `Root` frame laid out at `Config.UiReference` 1280x720 and scaled by one UIScale; flat components `text`/`box`/`edge`/`flatButton`/`iconButton`/`badge`/`chip`/`caption`/`panel`/`strip`/`rule`/`fitWidth` (wrappers carrying full-width edge bars are sized with `fitWidth`, never AutomaticSize, or they grow from their own bars); toasts and `payToast` slips under the pill), `StationMode.luau` (being at a station: holds the Workstation, one-line idle strip with the server's status, shows the first-visit tip), `StationTips.luau` (first-visit tip cards, saved via `Remotes.TipSeen` -> DataService `TipsSeen`, read from the player's `TipsSeen` attribute), `StationPicks.luau` (hover outline + click on pies: ready rack at Load → load, pies out of the oven at CutTable → pull), `Loading.luau` (Auto / Pick order-matching setting, the order picker), `WorkHud.luau` (tickets top-left by station `queue`: make-line orders, oven slots, heat rack; the Stations tab bottom-left with a Staff button beside it, collapsed by default, opening into a horizontal bar of station keys + Help / matching / Exit / Stores while hiding the work strip; the flashing Next button over the work strip; the oldest make ticket flashes; a Stores button when you're not at a store; fed by the server's 1/s `QueueUpdate` and `StepDone`), `Minigames.luau` (2D Register POS with topping toggles + Supply), `Minigames3D.luau` (in-world Stretch, Sauce, Cheese, Toppings, Cut & Box; each job gets its own folder and a `Ui.strip` work strip with controls only; the dough timing gauge is inside the strip), `Workstation.luau` (stand at the station, fixed camera from `Config.StationView` relative to the work spot; make stations aim straight at the spot so the pizza is dead centre; local character hidden, controls off, `pointerRay` works for mouse and touch), `Driving.luau`. Shared `Style.luau` (palette from `Config.Brand`, Oswald / Roboto Mono / Roboto faces, sizes, ticket colours) and `Icons.luau` (icons drawn from frames). `Prompts.luau` draws every ProximityPrompt (Style = Custom) as a charcoal card with a gold key chip and a hold line; the card is clickable. Shared `TicketRows.luau` (pure, specced) groups an order's pizzas into ticket rows, one line per topping ("PEPPERONI x3" / "MUSHROOMS", "1/3" while part-loaded, folded to "+N more"), used by the HUD tickets and the kitchen display. Server `Screens.luau` builds the in-world screens in the same look from plain data (kitchen display tickets, lobby order tracker steps, stock tablet, sales board); each rebuilds only when its content signature changes and ticks times/colours in place.

## Conventions
- Stations are invisible hitbox Parts with a `Station` attribute and a ProximityPrompt; art is parented underneath. Gameplay code finds things by name and attribute, never by appearance.
- Never hard-code store hours or staff kinds: use `GameClock.hoursText()` and `Config.Staff` / `Config.StaffOrder`.
- Shop-local coordinates: entrance faces +Z; Roblox's Front face is -Z (SurfaceGuis facing the street use `Back`). Station art: LookVector points at the worker.
- The client reports raw inputs only; validate every remote payload on the server.
- Road/lot surfaces are `CanCollide = false` so the car (it rides on four welded, low-friction cylinder "wheels") doesn't snag on seams. The car is hollow and sized for a seated character; only its lower body, bumpers and wheels collide, and exiting puts you beside the driver's door.
- Printed box lids are Front faces on parts laid flat with `BOX_FLAT` (Top-face SurfaceGuis read upside down from the front).
- Minigame input: Space / gamepad A, left click, or tap all count as the action button (`bindPress`); holds use mouse/finger on the 3D view.
- The DataStore key is still `PizzaShift_v1` (pre-rename); changing it orphans saves.
- Saves are session-locked (`DataService`: `claim` on load, `Save` only while this server holds `Lock`, `Release` lets go; `Config.Save`); never write player data with `SetAsync`. Specced in `tests/specs.luau`. The truck job refuses when every shelf is full and pays only for cases actually stored; carryout patience is 300 s (fixes from the 2026-10-19 audit, user-approved).

## Game design decisions (from the user)
- Direction (2026-10-19): moving from roleplay toward a tycoon/simulator. **No clock-in and no roles**: every player can work every station, the truck and deliveries. On joining, a player opens their own store on a free lot or joins an occupied one (up to 4 players, open to anyone; an owner lock may come later). 5 lots per server (lot 1 = the old HQ site). When the owner leaves, the longest-serving player takes over and the store reloads as their saved store (their staff); nobody is kicked.
- Delivery orders only come in with 2+ players at the store or a hired driver; otherwise those orders arrive as carryout (user's call).
- Staff (user's choices, 2026-10-19): a Staff menu from the start. **Team members** (bought, capped at 3 for now) work one station each, including the heat rack (driving). **Assistant and Store Managers** (from the roll; Studio-only grant for now, `GrantStaff`) can work several stations; **Flexibility** (managers only) sets how many before they're overwhelmed, and past that every job of theirs is slower and sloppier, so orders back up and sales are lost. Everyone has a **stat per station** (a level, raised by XP from jobs done there; each level makes them faster and better there), **reliability** (chance to call out of a shift: they miss it and the owner is told) and **availability** (which of the 3 shifts, Lunch / Dinner / Late Night, they can work; all 3 = "open availability", rare and sought after). The owner schedules who works each shift within availability. Buying (200 coins, rising) hires a random basic team member; rolls/spins (not built) will give better odds of high stats, open availability and managers. Ready for the roll: `Config.StaffRoll` (odds, cost, `Enabled = false`), `Staff.rollKind`, `Config.StaffGen` pools per kind, the menu's "Coming soon" row. Open: duplicates, what else managers do, coins vs Robux, the roll's team-member stat pool.
- Money: everyone keeps per-task pay and tips; the owner also earns `Config.Store.SaleCut` of every completed sale at their store (NPC-made too) and `OwnerRoyalty` on other players' pay.
- Menu (user, 2026-10-19, tentative): no specialty pizzas. A pizza is a size plus up to 3 toppings (`Config.MaxToppings`), each listed on its own ticket line; price = size + a price per topping (`Config.ToppingPrice`, Claude's numbers). Orders are `{ size, toppings }` (SalesPlan `rollToppings`, `name`, `describe`).
- Portions: by size and topping count (1 / 2-3), e.g. Large pepperoni 40/32. Pepperoni and ham are counted in pieces; the other toppings are weighed in ounces (`Config.CountedToppings`, `Config.PieceOz`: each piece put on weighs that much, so the client still reports piece counts). ±10% variance is allowed; beyond that, customer satisfaction drops (`Config.PortionFactor`). Only Large Pepperoni is spec'd; the other portions and cheese ounces are placeholders the user will supply.
- Pizza sizes are real proportions (10"/12"/14", `Config.PizzaInches`); 3D pizzas, dough skins and boxes all scale from them.
- Hours: open 10 AM to midnight every day; stations open at 9:30 AM to prep; at midnight everyone is sent off their station and the board is cleared. Players can explore any time.
- Sales: weekly $25k-$30k; Mon/Tue/Wed 10% each, Thu/Sun 15%, Fri/Sat 20%, each jittered ~3%; dayparts 10-4 = 20%, 4-9 = 70%, 9-12 = 10%. Orders are generated against that dollar budget, so order count follows the (daily-randomized) average ticket. Order sizes: small 1-4 pizzas (common), medium 5-15 (less common), large 15-30 (rare). Times in real minutes: load time = placed → all pizzas in the oven; total time = placed → all pizzas boxed.
- Tips scale with the order total: delivery tips go to the driver; carryout ("insider") tips are lower and split among the crew.
- Every dollar is a real order (user, 2026-10-19): there is no off-screen crew. Every forecast order comes to the store (a full lobby takes carryout online). Every order has a patience timer (`Config.OrderPatience`: 5 min + 75 s per extra pizza; walk-ins leave, phone/online/delivery orders are cancelled); what isn't done in time, goes to a wrong house, or is still open at midnight is a lost sale (`loseSale`, `sales.lostToday`, "LOST TODAY" on the sales board). Forecast = sales + lost + still open.
- Claude's calls on staff (tunable in Config, not the user's): price x1.25 per hire; at most 2 Assistant and 1 Store Manager; 8 on a shift; levels 1-20 (quality 0.5 -> 0.95, job time x1.5 -> x0.6); bought hires start at level 1-3 everywhere, reliability 3-8, available for 1/2/3 shifts at 50/40/10%; Assistant Managers level 3-6, reliability 5-9, Flexibility 2-6; Store Managers level 5-9, reliability 7-10, Flexibility 5-10; Flexibility F handles 1 + F // 2 stations (1-6), each one past that +50% job time and -15% quality; call-out chance 3% per reliability point short of 10; managers step between their stations without walking; staff don't sauce or top ahead of demand (dough is prep); staff walk straight through counters (no pathfinding).
- Multiple locations with different volumes and sales dynamics are planned but not designed yet (`AddShop(..., volume)` exists).
- Brand: the user chose "Dominus Pizza" after being warned it is close to "Domino's" and could draw a trademark claim. It's a single value, `Config.GameName`.
- Make process: every pizza physically exists at every step (skins on racks, sauced/cheesed pizzas waiting on the make-line, oven belt). Each step is its own station; players can work one station repeatedly (e.g. sauce 5 in a row) or follow one pizza start to finish via HUD buttons. Player autonomy and time management matter more than forced flow. In first person the player's hands are invisible (only tools show).
- Make-process guidance (user, 2026-10-19, so new players don't get lost): with nothing to work at a make station you're ALWAYS moved back a step, unless that step is occupied (by a player or NPC): then you wait on them. Stretch highlights the size the oldest ticket's top pizza needs (Claude also highlights it at Sauce). The Next button (was Follow) shows as soon as the pizza's next step is free, flashes white, sits centre-bottom over the work strip, and stays until used. The oldest ticket flashes. Physical over UI: weights show on make-line scales, toppings are picked from the pans on the rail.
- Stations are always available (multiplayer: nobody is locked out because nothing is waiting yet). You stay at a station after each minigame and leave manually; a HUD element moves you straight to another station. The order queue shows only during the make process. Mouse click and mobile tap work everywhere Space does. Camera at stations must be consistent and high enough to see the work (the user's reference image for the ideal angle never arrived; `Config.StationView` values are Claude's guess).
- Free-form make-line (user's design): pizzas aren't tied to orders until loaded; any finished pizza can be loaded, for any order or none. Toppings and portions must be memorized (no targets on screen; the scale shows what's on, not the target), the tip cards show them. Loaded pizzas show green with a check in the make-line queue until the whole order is loaded, then the order leaves that queue. Order matching is a per-player setting, Auto-match vs. Pick the order (user: "tentatively, for development, see if it sticks"). Finished pizzas wait on a 15-slot ready rack (screen rack like the dough racks) on its own table at the end of the make-line, worked from the Load Oven station; the user rejected a ready shelf that was "another makeline essentially".
- Ovens (user's design): 3 stacked conveyors, 2 lanes each = slots 1-6 (1-2 top, 3-4 middle, 5-6 bottom), loaded in order and wrapping; pizzas can follow closely but never overlap; real-time 120 s bake rendered moving down the belt. The oven tender has their own queue with countdowns, picks any pizza at the exit (white hover outline), clicks the right box in the world (not UI) and can move it to another box; faster rocker; graded on even slices (no crust seasoning: the user removed it 2026-10-19).
- Dough QTE (user's design): green zones vary in width and jump to a new spot after every hit (static during a press); more hits for bigger sizes; clear penalties for yellow/miss; the bar sits near screen center, apart from other UI. Sauce: endless spoodle, scored only on coverage and a clean rim (3/4" border, all sizes).
- Delivery: the heat rack is a station with its own queue; drivers pick which order to take.
- Claude's calls (not the user's): the next job auto-loads `Config.NextJobDelay` (0.8 s) after a step; two players at one station both stand on the same spot (each hides the other locally); an AFK player holding a job is taken off the station at the 120 s session timeout. Also: dough presses 6/8/10 and yellow = 45%; if the next slot's entrance is busy, loading skips to the next free slot (all busy = wait); pizzas back up behind one at the exit and only the front one's fall timer runs; cheese bubbles kept between boxing and cutting; a dropped pizza's order goes back on the make-line queue for a remake; customers who leave turn their pizzas into extras.
- Oven look (user's photos): stainless stacked conveyor ovens, no orange glow; each deck has a side door with a window so you can watch pizzas ride through (they exist the whole time: object permanence). A pizza can be pulled the moment it comes out of the chamber into open air, not only at the very end of the belt. Slot numbers are labeled the same way at both belt ends.
- Dough table layout follows the user's reference photos: screen racks stand on the table (not the floor) with stretched skins on dark screens; a big cornmeal pan in front of the racks; the stretch spot dusted with cornmeal; sauce tubs and the sauce spot on the same table off to the side; a backsplash. The photos run left to right toward their make-line; ours runs the other way, so the same order reads mirrored (racks and cornmeal farthest from the make-line). Positions live in `StationArt.Layout`.
- Make-line look follows the user's photo: stainless cabinet with end doors and a drawer bank, a wire grate work surface (pizzas ride on it), one long row of small black topping pans, a sloped stainless canopy over them; portion scales at the cheese and toppings spots (read-out to the maker's right, since the tip card sits on the left of the screen). Pans are grouped: cheese by the cheese spot, the six toppings in front of the toppings spot (the Toppings camera is a little shallower, 50°, so they sit below the tickets: Claude's call). Dough table extras from a photo of a worker stretching: blue dough box, green-handled spoodles.
- Dough stretching visuals follow the user's photo sequence: a dusted dough ball in a pile of cornmeal, pressed out into a lopsided disc with a rising edge that pushes the cornmeal into a ring, ending as a round, pale skin.

- UI overhaul (user-approved mockups, 2026-10-19; goal: stop looking AI-generated). "Store systems" look: the HUD reads like the store's own POS/kitchen-screen software. Flat, squared corners, brand charcoal / red / cream with gold and green accents (`Config.Brand`), no gradients or rounded pills. Type: Oswald (uppercase labels), Roboto Mono (numbers, timers), Roboto (rare body text). Icons are drawn in code from frames (no uploads). Layout: compact order tickets top-left (header goes green, then gold, then red as the order ages; loaded items struck through), only during the make process; one slim clock + coins + level pill top-right with toasts sliding in under it; at a station, a Stations tab bottom-left, **collapsed by default**, arrow pointing right, which expands **horizontally along the bottom** (station keys with waiting badges, Help, Exit, left arrow to collapse) while the work strip steps aside; a flashing Next button sits centre-bottom over the work strip; the work strip (bottom center) holds controls only, with no station title (user: redundant); the dough timing bar lives inside the work strip. **The pizza (or dough ball) is dead center in the station camera and no UI may cover it** (user: floating text obstructed the view; the camera looked slightly left of the work). Teaching: short labels plus a one-time first-visit tip card per station (reopen with ?). Scope: screen HUD and menus, the 2D Register/Supply minigames, and the in-world screens (kitchen screen, ready screens, sales board, job aids, box print). Mockup sources live outside the repo; the approved images are the toppings (collapsed / expanded) and stretch screens.
